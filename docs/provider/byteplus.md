# BytePlus Provider

Lucidio supports configured BytePlus ModelArk generation through the Express backend. The browser never calls BytePlus directly and never receives provider credentials.

## Architecture

- Image generation uses BytePlus Seedream models through `POST /api/v3/images/generations`.
- Video generation uses BytePlus Seedance models through `POST /api/v3/contents/generations/tasks`, then polls the provider task until completion.
- Generated media is uploaded to BytePlus TOS-compatible object storage.
- The frontend stores only metadata in IndexedDB: object keys, content types, thumbnails, provider task IDs, generation parameters, and project state.
- Preview, playback, and download use short-lived backend presigned URLs from `POST /api/media/presign`.

## Configuration

Copy the example config before using a real provider:

```bash
cp server/provider-config.example.yaml server/provider-config.local.yaml
```

By default the backend loads `server/provider-config.local.yaml` when it exists, otherwise it falls back to `server/provider-config.example.yaml`. Set `LUCIDIO_PROVIDER_CONFIG` to point at a different YAML file.

Keep secret values in environment variables referenced by the YAML file. Do not put secrets directly in the config.

Required ModelArk settings:

- `providers.byteplus.modelArk.baseUrl`: BytePlus ModelArk base URL, for example `https://ark.ap-southeast.bytepluses.com`.
- `providers.byteplus.modelArk.apiKeyEnv`: environment variable containing the ModelArk API key, usually `BYTEPLUS_MODELARK_API_KEY`.
- `providers.byteplus.modelArk.modelEndpointIds`: map from Lucidio model IDs to the endpoint IDs configured in the BytePlus account.

Required TOS settings:

- `storage.provider`: must be `byteplus-tos`.
- `storage.byteplusTos.endpoint`: TOS S3-compatible endpoint.
- `storage.byteplusTos.region`: TOS region used for request signing.
- `storage.byteplusTos.bucket`: bucket where generated media is stored.
- `storage.byteplusTos.accessKeyIdEnv`: environment variable containing the TOS access key ID.
- `storage.byteplusTos.secretAccessKeyEnv`: environment variable containing the TOS secret access key.
- `storage.byteplusTos.keyPrefix`: object-key prefix for generated media, defaulting to `generations` when omitted.
- `storage.byteplusTos.presignTtlSeconds`: maximum presigned URL TTL, clamped to at most 3600 seconds and rejected below 60 seconds.

Optional TOS setting:

- `storage.byteplusTos.publicBaseUrl`: explicit object base URL. If omitted, Lucidio derives a virtual-hosted URL from `endpoint` and `bucket`.

## Environment Variables

The example config expects:

```bash
export BYTEPLUS_MODELARK_API_KEY=...
export BYTEPLUS_TOS_ACCESS_KEY_ID=...
export BYTEPLUS_TOS_SECRET_ACCESS_KEY=...
```

Endpoint IDs are values in `server/provider-config.local.yaml`, not secrets. Replace the placeholder values such as `BYTEPLUS_ACCOUNT_ENDPOINT_ID_FOR_SEEDREAM_5` with real BytePlus endpoint IDs. Models with placeholder endpoint IDs are hidden from `GET /api/models`.

Seedream 5.0 Pro now uses catalog key `dola-seedream-5-0-pro-260628`; Seedream 5.0 Flash uses `dola-seedream-5-0-flash-260915`. If an existing local config maps the older `seedream-5-0-pro-260708` key, replace that key and point it to an endpoint for the current Pro model. Add a separate Flash endpoint mapping to enable Flash.

## Runtime Flow

1. The frontend calls `GET /api/models`.
2. The backend loads `server/model-catalog.yaml` and the provider config, then returns only catalog models with configured endpoint IDs.
3. The frontend posts generation requests to `POST /api/generate`.
4. The backend validates the request against the catalog and rejects unsupported top-level fields or provider params.
5. The backend calls BytePlus ModelArk using the configured endpoint ID.
6. Generated bytes are uploaded to TOS under a generated object key.
7. The job result returns stored media metadata to the frontend.
8. The frontend requests preview/download URLs through `POST /api/media/presign`.

Jobs are in memory. Restarting the server loses job status and active cancellation state, but completed media already uploaded to TOS remains in the bucket.

## Images

Seedream image requests are normalized before provider submission:

- `response_format` is forced to `b64_json`.
- `stream` is forced to `false`.
- `sequential_image_generation` is forced to `disabled`.
- `size` is derived from the selected Lucidio resolution and aspect ratio unless an allowed provider size is supplied.
- Reference images are passed as backend-generated presigned URLs.

The first provider pass stores one primary image asset per completed job.

## Videos

Seedance video requests are normalized before provider submission:

- `return_last_frame` is forced to `true` so Lucidio can store a thumbnail.
- `draft: true` is rejected because draft mode disables last-frame return.
- Resolution, ratio, duration, frame rate, audio, camera motion, and seed are validated against `server/model-catalog.yaml`.
- Camera motion maps to the inverse BytePlus `camera_fixed` parameter when that parameter is supported by the model.

Completed video jobs store two assets:

- The primary MP4.
- The returned last-frame thumbnail.

Cancellation updates local job state immediately. For active video jobs, the backend also aborts local provider work and best-effort cancels known BytePlus provider tasks. Provider cancellation is not durable across server process exits.

## References

References must be existing Lucidio-generated media metadata. Raw URLs, files, blobs, and data URLs are rejected at the API boundary.

Supported video reference intents are derived from the selected model capabilities:

- `image_reference`
- `first_frame`
- `last_frame`
- `source_video`

`audio_reference` and `sample_task` are reserved but not enabled in this provider pass.

For provider calls, Lucidio signs existing stored objects as short-lived preview URLs. If a video thumbnail is used as a reference, the thumbnail is signed as the referenced image asset.

## Media Keys And Presigned URLs

Object keys are generated by the backend under `storage.byteplusTos.keyPrefix`. They include a random token, job ID, generation ID, and a supported media extension.

`POST /api/media/presign` validates:

- `purpose`: `preview` or `download`.
- `assetRole`: `primary` or `thumbnail`.
- object key shape and configured prefix.
- content type and extension agreement.
- thumbnail requests only target image assets.

Presigned preview URLs use inline content disposition. Download URLs use attachment content disposition. Filenames default to `lucidio-<object-file-name>` when the caller does not provide one.

Local object keys are unguessable capability references for this local-first shell; they are not an ownership model. A future backend database/auth layer should introduce a server-owned media manifest before sync or multi-user access.

## Current Non-goals

This provider pass intentionally does not add:

- upload UI or arbitrary external reference URLs.
- backend database persistence.
- public object URLs.
- non-BytePlus providers.
- callback webhooks.
- real auth, billing, account management, or sync.
